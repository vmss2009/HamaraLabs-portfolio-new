# From Wires to a Working Game:

# How Rohan Built a Sort Game with Arduino

**Student:** Rohan V  
**Track:** Embedded Systems / Electronics Prototyping  
**Duration:** 1 month  
**Tools:** Arduino Uno, 8x8 LED Matrix, 7-Segment Display, Buzzer, Push Buttons | C++, Arduino IDE

![][image1]  
*Rohan's finished sort game setup*

## The Idea

Rohan wanted more than just a coding exercise — he wanted to understand how software and hardware actually talk to each other to create something people could use and enjoy. That idea turned into a hands-on sort game: a physical device built around an Arduino UNO, where an 8x8 LED matrix displays the game, a 7-segment display tracks the score, a buzzer gives audio feedback, and a set of keys lets the player interact in real time.

In Rohan's words:

*"It's a cakewalk. We can play with electronics."*

That mix of confidence and curiosity is exactly what this kind of project is designed to build.

## 

## Building It Piece by Piece

Rather than trying to wire everything at once, Rohan broke the project down into stages — starting simple and layering in complexity as each part worked:

1. Get a single component running on its own (starting with the LED matrix)  
2. Add the next component and confirm it worked alongside the first  
3. Write the game logic in C++ once the hardware foundation was stable  
4. Bring in the buzzer and 7-segment display for feedback and scoring  
5. Test the full system with real players

This phased, outcome-driven approach meant Rohan always had something working to test, instead of a pile of parts and code that only came together at the very end.

## Hitting (and Solving) Real Problems

Hardware projects rarely go smoothly on the first try, and Rohan's was no exception — he ran into **connection issues** getting all the components to communicate correctly. Instead of getting stuck, he used AI tools like ChatGPT, Gemini, and Claude as a sounding board to debug the wiring and code, working through the problem systematically until each connection was solid.

This is a big part of what the project was really teaching: not just Arduino syntax, but how to debug independently, use the resources available, and keep moving forward when something doesn't work the first time.

## Learning by Doing — With Real Structure

The project wasn't a loosely defined "figure it out" assignment. Rohan worked through a sequence of activities generated by the **HamaraLabs web application**, with each step building on the last — from understanding individual components to integrating them into a complete, working prototype.

By the end, Rohan had a tested prototype — not just something that worked on paper, but a device he tried out with real people and refined based on how they actually played it.

![][image20]![][image21]![][image22]![][image23]![][image24]![][image25]![][image26]![][image27]

## What Rohan Took Away

* How to connect hardware components (LED matrix, display, buzzer, buttons) and make them work together as one system  
* Writing C++ for embedded systems in the Arduino IDE  
* A structured way to tackle complex builds: start simple, test often, add complexity gradually  
* Independent debugging — including knowing when and how to use AI tools effectively as a learning aid  
* The satisfaction of taking an idea all the way to a usable, playable product
